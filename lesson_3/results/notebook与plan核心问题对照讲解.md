# Notebook 与 `plan` 核心问题对照讲解（新手版）

## 一、先理解两个文件分别负责什么

这两个文件不是两套不同的作业，而是同一件事的两个层次。

### `pbl-high-dimension-reduction-classroom.ipynb`

Notebook负责“做实验”。它读取数据、运行代码并产生数字和图片。它主要回答：

- 数据有多少患者和基因？
- 基因数量增加后，患者之间的距离怎样变化？
- 模型在见过的患者和未见患者中表现是否一样？
- 标准化后做PCA和UMAP，图形是什么样？

### `plan核心问题答案.md`

这个文件负责“解释实验”。它把Notebook和证据包中的数字组织成课程问题的答案，例如：

- 为什么这是高维数据？
- 为什么特征越多不一定越好？
- PC1到底代表什么？
- 为什么要标准化？
- PCA和UMAP有什么区别？
- UMAP图能说明什么、不能说明什么？

因此，正确的阅读顺序是：

```text
先看Notebook做了什么
        ↓
看Notebook输出了什么
        ↓
再看plan答案如何解释这些输出
```

如果直接从`plan核心问题答案.md`开始读，就会看到很多没有上下文的数字，所以容易感觉难懂。

---

## 二、两个文件共同讲述的一条主线

整节课其实只讲一条逻辑链：

```text
患者只有120人，但基因有23,146个
        ↓
这是“大p、小n”的高维数据
        ↓
维数增加后，距离和近邻可能越来越难解释
        ↓
模型容易在见过患者上取得很高分，但未见患者表现较低
        ↓
因此需要考虑标准化、特征压缩和降维
        ↓
PCA和UMAP可以把数据画成二维，但二维图一定有信息损失或形状扭曲
        ↓
所以不能把训练满分或漂亮的二维图直接当成可靠的临床发现
```

下面按照Notebook运行顺序，把它与`plan`中的问题逐项对应。

# 第一部分：数据载入——回答“为什么这是高维数据”

## 1. Notebook做了什么

Notebook读取：

```text
data/cohort120.npz
```

这个文件中主要有：

- `X`：基因表达矩阵；
- `y`：高危/非高危标签；
- `ids`：患者编号；
- `genes`：基因名称；
- `development`：80位开发组患者的位置；
- `test`：40位未见患者的位置。

代码检查：

```python
assert a["X"].shape==(120,23146)
assert len(X)==80 and len(a["test"])==40
```

`assert`可以理解为自动核对：如果数据不是120×23,146，或者不是80/40划分，程序就停止。

## 2. Notebook输出了什么

```text
Shape (120, 23146)
seen risk counts [53 27]
unseen risk counts [26 14]
```

解释如下：

| 输出 | 含义 |
|---|---|
| `120` | 120位患者，即样本数n |
| `23146` | 23,146个基因，即特征数p |
| `[53 27]` | 开发组有53位非高危、27位高危，共80人 |
| `[26 14]` | 未见组有26位非高危、14位高危，共40人 |

这里数组顺序是标签0、标签1，所以前一个数是非高危，后一个数是高危。

## 3. 这对应`plan`中的哪个问题

对应：

- 什么是高维数据？
- 为什么生物医学数据经常变量很多、样本很少？
- 什么是“大p、小n”？

## 4. 用最简单的话解释

本课数据中：

```text
n = 120位患者
p = 23,146个基因
```

所以：

```text
p/n = 23,146 ÷ 120 ≈ 192.9
```

意思是患者数量很少，但描述每位患者的基因特征特别多，这就是“大p、小n”。

重要的是：测量更多基因不会让患者数量增加。23,146个基因仍然来自同一批120位患者，不能当成23,146份独立患者证据。

## 5. 你可以怎样回答

> 本课数据有120位患者和23,146个基因，因此样本数n远小于特征数p，是典型的大p小n高维数据。每一行是一位患者，每一列是一个基因，一个数是患者某个基因的表达量。基因很多会增加信息量，但不会增加独立患者数量，因此统计估计和模型容易受到偶然波动影响。

## 6. 不能说什么

不能说：

- 有23,146个基因，所以样本量很大；
- 53位非高危就是53位健康人；
- 未见40人就是外部新中心患者。

高危与非高危都是神经母细胞瘤患者；未见40人仍来自同一研究来源。

# 第二部分：距离实验——回答“什么是维度灾难”

## 1. Notebook做了什么

Notebook分别使用：

```text
20、100、500、2,000、5,000、23,146个基因
```

每一种基因数量都先按基因标准化，再计算80位开发组患者两两之间的欧氏距离。

代码核心是：

```python
z=StandardScaler().fit_transform(X[:,order[:k]])
dd=squareform(pdist(z))
```

可以分成两步理解：

1. `StandardScaler`让不同基因处于大致可比的尺度；
2. `pdist`计算患者两两之间的欧氏距离。

## 2. 什么是欧氏距离

假设只看两个基因，患者A为`(1,2)`，患者B为`(4,6)`，欧氏距离为：

```text
√[(4−1)²+(6−2)²] = 5
```

基因表达越相似，距离通常越小；表达差异越大，距离通常越大。

但这个“相似”只是在当前基因、标准化和距离公式下的相似，不自动代表临床结局相同。

## 3. Notebook输出了什么

| 基因数 | 平均距离 | 平均最近距离 | 平均最远距离 | 相对对比度 |
|---:|---:|---:|---:|---:|
| 20 | 5.8405 | 3.2476 | 9.0782 | 1.9861 |
| 100 | 13.3181 | 8.7561 | 19.7307 | 1.3332 |
| 500 | 30.2314 | 21.6933 | 41.1559 | 0.9395 |
| 2,000 | 60.2031 | 44.3485 | 81.2832 | 0.8667 |
| 5,000 | 95.1976 | 70.5847 | 128.7353 | 0.8561 |
| 23,146 | 204.3323 | 151.1557 | 275.2609 | 0.8544 |

## 4. 每一列是什么意思

### 平均距离

80位患者一共有3,160对不重复的患者组合，平均距离是这些患者对欧氏距离的平均值。

### 平均最近距离

先为每位患者找到最近的另一位患者，再对80人的最近距离取平均。

### 平均最远距离

先为每位患者找到最远的另一位患者，再对80人的最远距离取平均。

### 相对对比度

对每位患者计算：

```text
(最远距离−最近距离) / 最近距离
```

再对80位患者取平均。这个指标越大，最近和最远的相对差别越明显；越小，远近越不容易区分。

## 5. 输出反映了什么

第一，绝对距离不断变大：

```text
平均距离：5.84 → 204.33
```

这是因为增加基因相当于增加坐标轴，每个新坐标都可能贡献一部分差异。

第二，相对对比度不断下降：

```text
相对对比度：1.99 → 0.85
```

这表示所有患者都变远了，但最近患者与最远患者的相对差别反而缩小。

## 6. 这对应`plan`中的哪个问题

对应：

- 为什么高维下距离可能变得不可靠？
- 什么是维度灾难？
- 为什么最近邻和最远邻的差异可能缩小？

## 7. `plan核心问题答案.md`为什么用了另一个20基因数字

Notebook第一种排列得到：

```text
20基因相对对比度 = 1.9861
```

证据包表B1汇总20种基因排列，得到平均：

```text
20基因相对对比度 = 2.3028
```

两者没有矛盾：

- `1.9861`是你实际运行的第一种基因排列；
- `2.3028`是20种排列的平均值。

汇报自己的Notebook时使用`1.9861`；讨论完整证据包时可以使用`2.3028`，但要说明来源。

## 8. 你可以怎样回答

> 在同一80位患者中，随着标准化基因数从20增加到23,146，平均欧氏距离从5.84增加到204.33，但相对对比度从1.99下降到0.85。说明高维下患者绝对距离增大，而最近与最远患者的相对区分程度下降，所以距离变大不等于患者更容易区分。

## 9. 不能说什么

不能说：

- 高维距离完全没有任何意义；
- 所有23,146个基因都是噪声；
- 500个基因一定最佳；
- 距离最近的患者一定属于相同亚型。

# 第三部分：见过与未见患者——回答“什么是过拟合”

## 1. Notebook做了什么

Notebook使用一个参数固定的逻辑回归分类器。

标准化器和模型只使用80位开发组患者拟合：

```python
sc=StandardScaler().fit(X[tr][:,idx])
model=LogisticRegression(...).fit(zt,y[tr])
```

随后，同一个模型分别预测：

- `seen`：参与模型拟合的80人；
- `unseen`：没有参与拟合的40人。

这里不是为了寻找最好的临床模型，而是演示训练表现与未见表现可能不同。

## 2. Notebook输出了什么

| 基因数 | 见过80人 | 未见40人 |
|---:|---:|---:|
| 20 | 73/80，91.25% | 30/40，75.0% |
| 100 | 80/80，100% | 31/40，77.5% |
| 500 | 80/80，100% | 35/40，87.5% |
| 2,000 | 80/80，100% | 35/40，87.5% |
| 5,000 | 80/80，100% | 35/40，87.5% |
| 23,146 | 80/80，100% | 34/40，85.0% |

## 3. 什么是过拟合

过拟合可以理解为：

> 模型不仅学到了能够推广的真实规律，还记住了训练患者中的偶然波动，所以对见过患者表现很好，对未见患者表现下降。

从100个基因开始，见过组全部达到100%，但未见组只有77.5%到87.5%。这说明训练满分没有完整迁移到未见患者，存在泛化差距。

但要注意：一次训练/未见差距只是过拟合风险的证据，不足以精确证明所有差距都来自过拟合。随机波动、患者构成和模型限制也可能影响结果。

## 4. 这怎样回答“特征越多为什么不一定越好”

未见组结果为：

```text
20基因：75.0%
100基因：77.5%
500基因：87.5%
2,000基因：87.5%
5,000基因：87.5%
23,146基因：85.0%
```

结果没有随着基因数量单调提高。全部基因并没有超过500到5,000个基因。

因此，增加特征可能：

- 增加有用信号；
- 增加重复信息；
- 增加噪声；
- 增加模型拟合自由度；
- 增加偶然相关。

## 5. 为什么还要看高危和非高危各自结果

使用20个基因时，未见组：

```text
高危：9/14 = 64.29%
非高危：21/26 = 80.77%
总体：30/40 = 75.0%
```

只看总体75%，会忽略模型对高危患者表现更差。

使用全部基因时：

```text
高危：12/14 = 85.71%
非高危：22/26 = 84.62%
```

两类表现比较接近。

## 6. 这对应`plan`中的哪个问题

对应：

- 为什么高维模型容易过拟合？
- 为什么特征越多不一定越好？
- 为什么训练高分不能代表新患者？

## 7. 你可以怎样回答

> 从100个基因起，模型在见过的80位患者中达到100%，但未见40人的正确率只有77.5%到87.5%。全部23,146个基因时，见过组80/80、未见组34/40，说明训练满分不能代表泛化能力。更多基因可能增加真实信号，也可能增加噪声、冗余和偶然拟合，因此是否更好必须根据未参与训练和调参的数据判断。

## 8. 不能说什么

不能说：

- 500个基因一定是最佳数量；
- 85%已经达到临床应用标准；
- 40位未见患者是外部新中心验证；
- 训练100%必然说明所有特征都是噪声。

不能根据这40人的结果反复选择基因数量，否则40人也会参与调参。

# 第四部分：标准化——回答“为什么PCA前通常需要标准化”

## 1. Notebook做了什么

```python
sc=StandardScaler().fit(X)
z=sc.transform(X)
```

这里的`X`是80×23,146开发组矩阵。

对每个基因计算：

```text
标准化值 = (原值−该基因均值) / 该基因标准差
```

## 2. 为什么要这样做

如果基因A本身波动范围特别大，基因B波动范围很小，不标准化时，基因A可能只是因为数值范围大，就主导欧氏距离和PCA。

标准化把大多数非恒定基因调整到：

- 均值约为0；
- 标准差约为1。

这样比较的是每个基因相对于自身正常变化范围的差异。

## 3. Notebook输出了什么

```text
mean -9.823454395715548e-18
median gene sd 1.0
```

第一个数约为：

```text
−0.0000000000000000098
```

在计算精度下可以认为等于0，所以标准化后的整体均值接近0。

第二个数表示基因标准差中位数为1，说明大多数基因已经处于可比较尺度。

## 4. 标准化与取对数是不是一回事

不是。

- `log2(1+FPKM)`：压缩偏斜和极端表达值；
- 按基因标准化：使不同基因的相对变化尺度可比。

本课数据已经是`log2(1+FPKM)`，所以不再取对数，但仍然可以按基因标准化。

## 5. 标准化一定更好吗

不一定。标准化也可能把一个原本变化很小、主要包含测量噪声的基因放大到单位方差。因此应该根据研究目的比较仅中心化和标准化，并报告具体处理。

## 6. 你可以怎样回答

> PCA前通常按基因标准化，是为了避免高方差基因仅因为数值尺度较大而主导主成分。本次标准化后矩阵均值约为0，基因标准差中位数为1，说明不同基因进入了大致可比尺度。但标准化也可能放大低变异基因中的噪声，所以不是没有代价。本数据已经是log2(1+FPKM)，不需要再次取对数。

# 第五部分：PCA——回答“PC1到底代表什么”

## 1. Notebook做了什么

```python
pc=PCA(n_components=2,svd_solver="full").fit(z)
xy=pc.transform(z)
```

输入`z`为：

```text
80位患者 × 23,146个标准化基因
```

输出`xy`为：

```text
80位患者 × 2个主成分得分
```

也就是把每位患者从23,146个数压缩成两个数：PC1得分和PC2得分。

## 2. PCA是怎样压缩的

PCA不是从23,146个基因中挑两个基因，而是把所有基因按权重组合成新的方向。

可以把PC1写成：

```text
PC1 = 权重1×基因1 + 权重2×基因2 + …… + 权重23146×基因23146
```

PC1选择的是患者投影后方差最大的方向。PC2与PC1垂直，并继续解释剩余方差中最大的部分。

## 3. Loading和score分别是什么

- Loading：属于基因，是基因在主成分中的权重；
- Score：属于患者，是患者投影到主成分后的坐标。

例如，MKNK1的PC1权重为`+0.0165`，PAICS为`−0.0162`。这些权重共同定义PC1方向。某位患者把自己的标准化表达值按这些权重加起来，才得到自己的PC1得分。

## 4. Notebook输出了什么

```text
PCA ratios [0.14493162 0.08263467]
```

意思是：

```text
PC1解释14.49%方差
PC2解释8.26%方差
累计解释22.76%方差
```

因此，二维PCA图仍然没有显示约77.24%的方差。

## 5. `plan核心问题答案.md`中“51维达到90%”从哪里来

Notebook课堂代码只计算两个主成分，所以只直接输出14.49%和8.26%。

证据包表C2进一步计算了更多主成分：

```text
2维：22.76%
20维：67.40%
51维：90.09%
79维：接近100%
```

所以“51维达到约90%”来自证据包，不是当前Notebook代码直接打印的结果。

## 6. 为什么最多是79个有效主成分

PCA使用80位开发组患者。中心化后，80个样本最多只有：

```text
80−1=79
```

个独立变化方向。

这不表示只存在79个有用基因，而是当前80位患者最多支持79个非零线性变化方向。

## 7. PC1能不能叫“高危轴”

不能。PC1只知道哪里方差最大，不知道高危标签，也不知道疾病机制。

PC1可能混合：

- 真实生物差异；
- 年龄、分期、MYCN状态；
- 技术批次；
- 异常值；
- 其他未测量因素。

另外PC1整体正负号可以反转，所以正方向不自动表示更高风险。

## 8. 你可以怎样回答

> PC1是23,146个标准化基因按loading加权形成的线性方向，使80位患者投影后的score方差最大。本数据PC1解释14.49%的总方差，PC2解释8.26%，二维累计22.76%。PC1不是某个基因，也不自动代表高危程度或生物学通路；给它命名需要loading、临床和独立验证证据。

# 第七部分：UMAP——回答“为什么它看起来分得更开”

## 1. Notebook做了什么

```python
um=UMAP(
    n_neighbors=15,
    min_dist=.1,
    random_state=SEED,
    n_jobs=1
).fit(z)
```

输入仍然是同一批80位患者和全部23,146个标准化基因。

主要参数：

- `n_neighbors=15`：重点考虑每位患者附近约15个局部邻居；
- `min_dist=0.1`：控制二维图中点能够靠多近；
- `random_state=20260921`：固定随机种子。

## 2. UMAP与PCA最关键的区别

PCA主要保留总体线性方差；UMAP主要尝试保留局部邻域关系。

因此UMAP可能把局部相似患者拉到一起，把不同邻域在二维图中推开，使簇和空隙看起来更明显。

## 3. UMAP坐标轴是什么意思

UMAP 1和UMAP 2只是二维布局坐标：

- 不是第一、第二重要生物方向；
- 没有解释方差比例；
- 整体旋转或翻转通常不改变含义；
- 坐标数值大小本身没有临床意义。

## 4. 实际图中观察到什么

- 左下方出现一个以红色高危患者为主的局部区域；
- 右侧主体区域以蓝色非高危患者为主；
- 左下区域不是绝对只有红色；
- 右侧也存在红色患者；
- 风险标签与局部结构有一定关系，但没有完全一致。

可以说：

> 在当前标准化、参数和种子下，UMAP显示一个以高危患者为主的局部区域，值得进一步核查。

不能说：

> UMAP已经发现一个新的高危生物学亚型。

## 5. 为什么不能直接相信空隙和簇

UMAP图形可能受到：

- `n_neighbors`；
- `min_dist`；
- 随机种子；
- 标准化方式；
- 技术批次；
- 患者临床构成。

图中的簇间距离、面积和密度也不等于原始高维空间中的真实距离、患病严重度或亚型大小。

## 6. `plan答案`中的近邻保留率从哪里来

课堂Notebook只画了一个基准UMAP，没有直接计算近邻保留率。

证据包表C3计算了相对于原标准化空间的五近邻保留率：

```text
二维PCA：25.75%
基准UMAP：40.25%
UMAP仅改种子：40.50%
UMAP仅改近邻数：41.50%
UMAP仅改最小间距：39.75%
```

这说明本设置下UMAP平均保留了比二维PCA更多的原空间局部近邻，但40.25%仍然不是100%。

## 7. 你可以怎样回答

> UMAP主要用于探索高维数据的局部邻域。本图在固定参数和随机种子下出现一个以高危患者为主的左下区域，但红蓝仍然混合。UMAP坐标轴没有直接生物学含义，簇和空隙会受参数、随机种子和批次影响，因此只能作为探索线索，不能单凭图形命名新亚型或证明预测能力。

# 第八部分：PCA与UMAP怎样对比

| 比较 | PCA | UMAP |
|---|---|---|
| 方法 | 线性降维 | 非线性降维 |
| 主要目标 | 保留最大总体方差 | 尽量保留局部邻域 |
| 坐标轴 | 有主成分含义 | 只是布局坐标 |
| 能否报告解释方差 | 可以 | 不可以用相同方式报告 |
| 是否容易解释基因贡献 | 可检查loading | 坐标本身难直接解释 |
| 参数和随机性 | 相对稳定 | 对参数和种子更敏感 |
| 适合用途 | 可解释的压缩和概览 | 局部结构探索和可视化 |
| 主要风险 | 二维损失大量方差 | 容易把图形当成真实簇和距离 |

两张图看起来不同，不代表其中一张正确、另一张错误。它们优化的目标不同。

UMAP看起来分得更开，也不代表：

- 保留了更多总方差；
- 分类更准确；
- 发现了真实亚型；
- 比PCA在所有用途上都更好。

# 第十部分：把十个`plan`答案压缩成新手能说的版本

## 1. 什么是高维数据？

本数据只有120位患者，却有23,146个基因。患者数n远小于特征数p，所以是大p小n高维数据。更多基因不会增加独立患者数量。

## 2. 什么是维度灾难？

维数增加后，空间变得稀疏，需要更多患者才能覆盖。Notebook中平均距离从5.84升到204.33，但相对对比度从1.99降到0.85，说明患者都变远了，远近的相对区别却减弱。

## 3. 为什么特征越多不一定越好？

更多特征可能带来信号，也可能带来噪声、冗余和偶然相关。全部基因时见过组80/80，但未见组34/40，说明训练满分不等于泛化可靠。

## 4. 降维是用于可视化还是建模？

两者都可以。二维PCA和UMAP适合展示，多维PCA可能作为模型输入；但图上分得开不能代替未见患者评价。

## 5. PC1是什么？

PC1是所有基因按权重组合出的线性方向，使患者投影后的方差最大。本数据PC1解释14.49%，它不是某个基因，也不是高危程度。

## 6. 为什么通常需要标准化？

标准化防止高方差基因仅因数值范围大而主导距离和PCA。本次标准化后均值约0、基因标准差中位数1，但标准化也可能放大低变异噪声。

## 7. PCA和UMAP有什么区别？

PCA是线性的、可报告解释方差和loading；UMAP是非线性的，更强调局部邻域，但轴没有直接含义，结果更依赖参数和种子。

## 8. UMAP能说明什么？

可以说在指定参数下观察到以高危患者为主的局部区域。不能凭簇、空隙或簇间距离直接宣布新亚型、因果关系或预测能力。

## 9. 怎样避免过度解释？

报告数据、标准化、参数、种子和解释方差；同时描述分离与重叠；核查近邻、参数敏感性、临床变量和技术批次；再用独立患者验证。

## 10. 最后应该怎样展示？

可以用PCA作为主要低维概览，并明确二维只解释22.76%；UMAP作为辅助局部探索，同时报告参数和限制。建模时所有标准化、PCA和选择步骤必须只在训练侧拟合。

# 第十一部分：最适合课堂汇报的一条完整回答

> 本课数据包含120位神经母细胞瘤患者和23,146个基因，是典型的大p小n高维数据。距离实验显示，随着基因数从20增加到23,146，平均欧氏距离从5.84增加到204.33，但相对对比度从1.99下降到0.85，说明绝对距离增大，而患者远近的相对区分程度下降。固定分类器从100个基因起在见过80人中达到100%，但未见40人的正确率只有77.5%到87.5%；全部基因时为80/80对34/40，说明训练满分不能代表泛化。标准化后，PC1和PC2分别解释14.49%和8.26%，二维累计只解释22.76%，所以PCA图只是有损概览。UMAP显示一个以高危患者为主的局部区域，但图形依赖参数和种子，坐标轴、簇间距离和空隙不能直接解释为生物学亚型。因此，我会用PCA及解释方差作为主要概览，把UMAP作为辅助探索，并要求训练侧处理、参数稳定性、批次核查和独立患者验证。
